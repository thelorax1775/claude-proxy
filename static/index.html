One-time setup. Save the block below as settings.json and every claude session on that machine goes through this proxy — no variables to re-export in each new terminal.

Proxy address

where claude sends requests

That isn't a loopback address, so the proxy has to be bound to an interface it's reachable on — set PROXY_HOST in .env and restart, or claude gets a refused connection.

settings.json


      

        Save as ~/.claude/settings.json for every project, or
        .claude/settings.json inside one project for just that one.
        On Windows that's %USERPROFILE%\.claude\settings.json. If the
        file already exists, merge the env block into it rather than
        replacing the whole file. Claude Code picks it up on next launch.

        Should print {"status":"ok",...}. Then run
        claude and ask it something; the Backends tab's
        “Recent attempts” will show which backend served it.

          different proxy.

Worth knowing

      

      

        The API key above is an unchecked placeholder — this proxy has no
        auth, and Claude Code just refuses to start without something set. Your
        real provider keys live in backends.json and never leave the
        proxy's machine. Which model actually answers is decided by the
        Backends tab, not by the model name Claude Code sends: anything
        containing haiku maps to that backend's fast model,
        everything else to its default model.
